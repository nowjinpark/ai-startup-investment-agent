# 자료 수집

1번 에이전트는 NAVER D2SF·카카오벤처스·본엔젤스·퓨처플레이 등의 공개 포트폴리오와 StartupRecipe에서 후보를 찾고 기업·고객·투자사 자료를 보완합니다. 자료를 PDF로 보관하고, 저장한 페이지의 본문을 RAG에 전달합니다. 링크나 검색 요약만으로 투자 근거를 만들지 않습니다.

## 담당자 수정 위치

- `config/sources.json`: 조사 사이트·용도·접근 방법
- `collection.py`: 공개 HTML·PDF 읽기, 본문 정리, PDF 보관, 쪽수 제한
- 후보 검색 질문과 회사별 URL 선정: `agents/discovery.py`

## 사이트별 처리

| 자료 | 현재 처리 | 보완 방법 |
|---|---|---|
| VC 공개 포트폴리오 | 로봇 분야 소개·투자 목록 HTML/PDF 수집 | 기업 카드 안의 이름과 제품 설명을 함께 확인 |
| StartupRecipe 투자 표 | 공개 HTML 수집 | 공식 투자 발표로 최신 단계 확인 |
| 기업·고객·투자사 홈페이지 | 공개 HTML·직접 PDF 주소 수집 | 제품/뉴스/IR 상세 주소 지정 |
| PwC 보고서·IFR 공개 뉴스 | 공개 본문·PDF 수집 | 기업과 관련된 세부시장 자료 선택 |
| KIRIA 보고서 | 공개 PDF 직접 주소 수집 시도 | 접속 실패 시 공개 PDF를 직접 저장해 추가 |
| KIPRIS·ScienceON | 공개 원문 PDF 입력 | 검색 UI/API 전용 연동은 추가 개발 |
| 나라장터·벤처나라 | 공개 계약·실적 자료 파일 입력 | 사용할 공식 API의 신청·명세 확인 후 연결 |
| KIND·DART | 공개 조회 결과·공시 파일 입력 | 자동 검색/API 전용 연동은 추가 개발 |
| THE VC | 공개된 기업 정보만 활용 | 로그인·유료 항목은 공식 자료로 보완 |

확인일과 접근 확인 범위는 `config/sources.json`에 있습니다. 웹 검색 도구에서 읽힌 사이트라도 로컬 수집에서는 robots.txt나 사이트 응답에 따라 실패할 수 있습니다. 수집되지 않은 사실은 `collection_errors.json`에 남습니다.

2026-09-30 실제 수집 시험에서 StartupRecipe 투자 표는 A4 38쪽으로 변환되었고 PwC PDF는 46쪽으로 읽혔습니다. 시험 한도를 문서당 2쪽·전체 4쪽으로 설정했을 때 각각 2쪽만 저장하고, 미수집 36쪽·44쪽을 기록했습니다. 접속 가능 여부는 실행 시 다시 확인합니다.

## 쪽수와 출처

- 세 에이전트의 자료 전체를 한 `Collector`와 한 출력 폴더로 관리합니다.
- 수집 종료 후 `corpus/rag-documents.pdf`로 실제 사용 페이지를 합칩니다. 책갈피에서 출처 ID를 확인하고 `sources.json`의 원본 주소·쪽수와 대조할 수 있습니다. JSON은 출처 목록이며 PDF 쪽수를 대신하지 않습니다.
- PDF는 원본 페이지를, 웹 본문은 A4로 실제 생성한 PDF 페이지를 셉니다. 최대 200쪽을 넘는 페이지는 저장하지 않습니다.
- 기본적으로 한 문서에서 최대 8쪽을 수집합니다. 첫 8쪽이 분석에 적합하다는 뜻은 아닙니다. `pages=[6, 7, 12]`처럼 실제 PDF 쪽수를 지정하면 해당 쪽만 수집하고 원본 쪽수도 유지합니다. 지정한 쪽에도 문서별·전체 쪽수 제한이 적용됩니다.
- 같은 본문의 페이지는 한 번만 저장합니다. 같은 회사에서 기술·시장 역할이 함께 쓰면 `doc_types`를 공유합니다.
- 다른 회사에 배정된 동일 문서는 기업 ID를 임의로 바꾸지 않습니다. 공통 산업 자료의 기업 ID는 `__sector__`입니다.
- 원본 쪽수, 본문, URL, 수집 시각, 공개 발행일을 저장합니다. 발행일이 없는 자료는 추정하지 않습니다.
- 스캔·이미지뿐인 페이지는 근거 본문으로 사용하지 않습니다. OCR 후 원문과 대조한 자료로 추가합니다.

## 파일 추가

직접 받은 공개 PDF는 `data/raw/`에 넣고 `data/local_sources.json`에 아래 형식으로 등록합니다. 파일명·회사명·원문 주소는 실제 자료로 바꿉니다. 공통 시장 보고서는 `company_name` 대신 `"company_id": "__sector__"`를 사용합니다.

```json
[
  {
    "file": "raw/기술자료.pdf",
    "company_name": "실제 법인명",
    "doc_type": "technology",
    "url": "https://실제-원문-주소",
    "title": "실제 자료 제목",
    "pages": [2, 3, 6]
  }
]
```

`doc_type`은 기업 정보 `company`, 기술 `technology`, 시장·사업 `market` 중 하나입니다. 회사명은 자동 후보 목록의 이름과 맞춰 주세요. 이름이 같아도 대표·사업·법인이 다르면 합치지 않습니다.

## 사용 예시

```python
from collection import Collector

collector = Collector({"max_pages": 200, "max_pages_per_source": 8}, "output/run/corpus")
pages = collector.collect(
    "https://startuprecipe.co.kr/invest",
    company_id="__discovery__",
    doc_type="company",
)

# 사용자가 공개 페이지에서 저장한 실제 자료
pages = collector.add_local(
    "data/selected_report.pdf",
    company_id="__sector__",
    doc_type="market",
    url="실제 원문 주소",
    title="자료 제목",
    pages=[6, 7, 12],
)
print(collector.page_count)
```

자료를 추가한 뒤 `sources.json`의 `company_id`, 본문과 원본 PDF를 확인합니다. 등록특허 0건, 유료 고객 0명, 비상장 여부는 단순히 검색 결과가 없다는 이유로 확정하지 않습니다. 나라장터 실적은 공공 고객 거래에 한정되므로 기업 전체 매출로 해석하지 않습니다. 과거 설치량 증가율과 미래 매출 시장의 예상 CAGR도 구분합니다.

`data/local_sources.json`에도 `"pages": [6, 7, 12]`를 넣을 수 있습니다. 인쇄된 장표 번호가 아니라 파일 뷰어의 첫 쪽을 1로 센 쪽수를 사용합니다. 웹 자료에 `pages`를 지정하면 A4로 변환한 PDF의 쪽수를 선택합니다.

## 접근 제한

공개 HTTP(S) 주소만 처리합니다. 내부망 주소·로그인·캡차를 우회하지 않습니다. robots.txt 확인, 요청 간격, 연결 시간, 다운로드 크기 제한을 적용합니다. 승인한 공식 API는 별도로 연동해야 하며 이 코드에는 확인되지 않은 API 주소를 넣지 않았습니다.

## 확인 명령

```bash
./.venv/bin/python -m unittest discover -s tests -p 'test_collection.py' -v
RUN_NETWORK_TESTS=1 ./.venv/bin/python -m unittest discover -s tests -p 'test_collection.py' -v
```

첫 번째 명령은 실제 API·네트워크 없이 쪽수 상한, 중복, 원본 페이지, 오류 기록, 내부망 차단을 확인합니다. 두 번째는 공개 웹·PDF 접근을 추가 확인하며 사이트 상태에 따라 실패할 수 있습니다.

## 준비 자료 재사용

`data/prepared/`에는 완료 표시, 문서 목록·원문 PDF, 기업 후보와 제외 기록을 함께 저장합니다. 기본 실행에서는 이 자료를 읽고 새로운 웹 수집·후보 추출을 하지 않습니다. 최초 149쪽에 공식 시장·경쟁 자료 15쪽을 보완한 현재 자료는 164쪽입니다. 200쪽까지 채우지 않습니다.

새 자료가 필요할 때만 `main.py live --refresh-data`를 새 출력 폴더로 실행합니다. 기존 자료는 `data/prepared-backups/`에 남습니다. 문서 해시·쪽수·후보 출처·조사 조건이 맞지 않으면 중단하며 자동 유료 수집으로 전환하지 않습니다. 준비 자료 재사용과 기술·시장 분석 재실행은 별개입니다.
