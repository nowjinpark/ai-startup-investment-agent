# 수업 코드와 구현 검토

2026-09-30에 보관된 수업 노트북과 「RAG Pipeline 설계 및 구축」 강의 PDF를 현재 코드와 직접 대조했습니다. 핵심 구조는 수업에서 사용한 **문서 분할 → 임베딩 → 검색 → 근거 기반 답변**, **State → Node → Edge**입니다. 웹 수집, 기업 평가, 출처 검수, PDF 출력은 과제에 맞게 추가한 부분입니다.

## 수업 예제와의 연결

노트북 경로는 수업 자료의 `ai-service/` 폴더를 기준으로 표시했습니다. 셀 번호는 마크다운을 포함해 위에서부터 센 순서이며 실행 번호가 아닙니다. PDF 쪽수는 뷰어 기준입니다.

| 기능 | 직접 확인한 수업 자료 | 현재 구현과 차이 |
|---|---|---|
| 문서 로딩 | PDF 29~30쪽의 외부 자료 수집·전처리·로딩 | `collection.py`에서 웹 본문과 PDF를 읽습니다. 실제 200쪽 제한과 원문 보관을 위해 수업의 PDFLoader 대신 pypdf와 웹 수집 코드를 사용합니다. |
| 문서 분할 | `langchain-v1/11-TextSplitter/01-RecursiveCharacterTextSplitter.ipynb` 8~9번째 셀, PDF 32~33쪽 | `rag.py`의 `RecursiveCharacterTextSplitter`를 그대로 사용합니다. 청크 크기와 겹침만 과제 설정인 700자·100자로 조정했습니다. |
| 임베딩 재사용 | `langchain-v1/12-Embedding/02-CacheBackedEmbeddings.ipynb` 5~11번째 셀 | 같은 `CacheBackedEmbeddings.from_bytes_store`와 `LocalFileStore`를 사용합니다. 임베딩 모델을 OpenAI에서 BGE-M3로 바꾸고 검색어 임베딩도 저장합니다. |
| 벡터 저장소와 검색 | `langchain-v1/13-VectorStore/01-FAISS.ipynb` 11·49~50번째 셀, `14-Retriever/01-VectorStoreRetriever.ipynb` 5~6번째 셀 | `FAISS.from_documents`와 `as_retriever(...).invoke(question)`을 사용합니다. 다른 회사의 실적이 섞이지 않도록 회사별 검색 범위를 추가했습니다. |
| 검색 결과를 이용한 답변 | `langchain-v1/15-RAG/01-RAG-Basic.ipynb` 31번째 셀 | 수업처럼 검색 결과와 질문·규칙을 프롬프트에 넣습니다. `common.py`에서 프롬프트와 LLM을 연결하고, 다음 에이전트가 읽을 수 있도록 정해진 JSON 형식으로 받습니다. |
| 상태와 조건 분기 | `langgraph-v1/00-Basic/02-State.ipynb`, `03-Graph.ipynb` 47·67~68번째 셀, PDF 142~147쪽 | `models.py`의 `GraphState`와 `workflow.py`의 `StateGraph`, `add_node`, `add_edge`, `add_conditional_edges`를 사용합니다. 통과 기업 수와 후보 목록 소진 여부로 종료를 결정합니다. |
| 병렬 분석과 합류 | `langgraph-v1/01-Features/21-Branching.ipynb` 9번째 셀의 `add_edge(["b2", "c"], "d")` | 같은 방식으로 기술 분석과 시장 분석이 모두 끝난 뒤 투자 판단을 실행합니다. 두 분석은 서로 다른 State 항목을 갱신합니다. |
| 검색 품질 평가 | `langchain-v1/14-Retriever/10-Retriever-Evaluation.ipynb` 15번째 셀, PDF 85~86쪽 | `evaluate_retrieval.py`에서 Hit Rate@K와 MRR@K를 계산합니다. 수업의 본문 겹침 판정 대신 정답 페이지의 `source_id`로 확인합니다. 평가 단위가 달라 수업 실험과 점수를 직접 비교하지 않습니다. |

수업의 `14-Retriever/04b-BGE-M3.ipynb`는 BGE-M3의 sparse 검색과 OpenAI dense 검색을 합치는 예제입니다. 이번 코드는 **BGE-M3의 dense 임베딩만** 사용합니다. 따라서 해당 노트북을 그대로 복사했거나 sparse·ColBERT 검색까지 구현했다고 설명하지 않습니다.

## 과제용 추가 기능

| 추가 코드 | 필요한 이유 |
|---|---|
| `collection.py` | 팀이 정한 사이트에서 자료를 수집하고 원문·출처·실제 PDF 쪽수를 보관합니다. |
| `prepared_data.py` | 이미 만든 문서와 후보 목록을 다시 사용해 불필요한 수집 비용을 줄입니다. |
| `common.py`, `evidence_audit.py`, `grounding.py` | 인용문이 실제 원문에 있는지, 그 인용이 평가 내용을 뒷받침하는지 점검합니다. LLM 검수도 오판할 수 있어 원문 대조 기록을 별도로 남깁니다. |
| `agents/investment.py`, `config/rubric.json` | AI가 추출한 사실에 팀의 평가표를 적용합니다. 점수 합산과 통과 여부는 Python 코드가 결정합니다. |
| `agents/report.py` | 분석 결과를 점수순으로 정리하고 SUMMARY·본문·REFERENCE를 포함한 PDF를 만듭니다. |
| 실행 기록·비용 기록 | 실행 중단 후 원인을 확인하고, 이미 지출한 API 비용과 새 실행 비용을 구분합니다. |

회차별 자료 복사와 인용 검사는 수업의 필수 API는 아니지만, 이번 과제의 비용·쪽수·출처 요구를 처리하는 코드입니다. 별도 서버나 새로운 에이전트 프레임워크를 추가하지 않았습니다.

## 평가표 변경

팀 논의에 따라 기존 1·4·5·9번을 점수 계산에서 제외합니다. 남은 2·3·6·7·8·10번의 상·중·하는 각각 3·2·1점이며, 최대 18점입니다. 설정에는 표시 순서 1~6을 두고, 보고서 평가표에는 원 설계 번호 2·3·6·7·8·10을 표시하여 근거 기록과 연결합니다.

통과 기준은 **12점 이상**입니다. 여섯 항목이 모두 ‘중’이면 12점이므로 초기 기업의 실증·고객 접점·과금 구조를 확인했을 때 비교 후보로 올릴 수 있는 기준입니다. 기존 24/30점의 평균 2.4점에서 평균 2점으로 완화한 팀의 과제용 기준이며, 검증된 투자 수익 예측 기준은 아닙니다.

확인하지 못한 항목을 임의의 ‘중’으로 채우지 않습니다. 여섯 항목을 모두 확인해 12점 이상이면 점수 기준을 충족합니다. 기업 자격까지 확인한 추천 기업과, 추가 자격 확인이 필요한 조건부 검토 기업을 구분합니다. 두 유형을 합쳐 후보 5개를 확보하면 종료하며, 후보가 부족하면 확보한 결과와 보류 사유로 보고서를 만듭니다. 세부 계산과 미확인 처리는 [평가기준](평가기준.md)을 따릅니다.

시장 규모·성장성, 기술 차별성, 팀 전문성, 기술·운영 위험은 **점수 항목에서만 제외**합니다. 과제에서 요구하는 보고서 내용이므로 기술·팀·시장·위험 설명에는 확인한 근거와 한계를 계속 남깁니다.

## 자료와 비용

최초 준비 자료 149쪽에 공식 시장·경쟁 자료 15쪽을 보완하여 현재는 164쪽입니다. `data/prepared/`의 원문과 후보를 재사용하며, 평가표를 바꾸기 위해 새 문서 200쪽을 만들지 않습니다. 200쪽은 최대 한도입니다.

- 저장된 분석 결과의 재채점과 보고서 작성: API 호출 없이 가능합니다.
- 기본 `live`: 문서 수집은 생략하지만 기술·시장 분석과 검수 API 비용은 발생할 수 있습니다.
- `--refresh-data`: 사용자가 지정할 때 문서·후보를 새로 수집합니다.
