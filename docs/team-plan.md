# 5명이 함께 만드는 방법

## 먼저 20~30분 함께 정할 것

1. 분석할 분야와 회사 후보. `project.json`에 기록합니다. 회사는 나중에 바꿀 수 있습니다.
2. 각자 A~E 중 맡을 일. 김민정·김희윤·박종찬·박진원·이현우의 역할은 아직 미정입니다.
3. `agents/state.py`의 정보 이름과 `data/example.json`의 예제 결과 형식.
4. 평가 항목·점수 기준·근거가 없을 때 처리. `evaluation.json`은 합의 전 초안입니다.
5. 자료 출처·페이지 수 기록, 실행 환경과 패키지 버전.

처음 합의한 정보 이름을 바꿀 때는 팀에 알립니다. 예를 들어 한 사람은 `summary`, 다른 사람은 `answer`라고 쓰면 연결할 때 다시 고쳐야 합니다.

## 그다음에는 각자 진행

| 담당 | 할 일 | 다른 사람을 기다리지 않고 시작하는 방법 |
|---|---|---|
| A | 자료 읽기·나누기·출처 기록, 기업 기초정보 | 작은 PDF 한 개로 시작 |
| B | 오픈 임베딩·검색·기술 요약 | 예제 문서로 검색을 먼저 완성 |
| C | 시장·경쟁사 분석 | 예제 검색 결과로 분석 함수부터 작성 |
| D | 실적·투자조건 확인, 점수·판단, 보고서 내용 | 예제 분석 결과로 계산·보류 처리 작성 |
| E | State·작업 순서·분기·PDF 출력 | 각 함수가 예제 결과를 주는 상태로 먼저 연결 |

자료 조사는 전원이 자기 분야에서 합니다. A가 모든 자료를 혼자 모을 필요는 없습니다.
D는 **무슨 내용을 쓸지**, E는 **어떤 순서로 실행하고 파일로 저장할지**를 맡습니다.
E에게 연결 오류를 모두 맡기지 말고 각자 자기 함수의 오류를 고칩니다.

**프로그램 실행 순서가 개발 순서는 아닙니다.** 예제 입력으로 동시에 만들고, 실제 결과가 나오면 바꿔 연결합니다.

## 함께 확인할 것

- 중간에 한 번 전체 실행. 끝날 때까지 따로 개발하지 않습니다.
- 실제 자료 → 검색 → 분석 → 판단 → 보고서에 출처가 이어지는지 확인.
- 검색 자료가 부족할 때 재검색하거나 보류하는지 확인.
- 보류하면 다음 후보로 가고, 후보를 다 보면 종료하는지 확인.
- 다른 팀원이 README만 보고 실행해 보기.
- 보고서의 숫자·출처·5쪽 제한 확인. README도 각자 자기 부분 작성.

## GitHub 사용

1. 작업 전 최신 변경을 받습니다.
2. 각자 작업용 브랜치에서 자기 파일을 수정합니다.
3. 실행 결과를 확인한 뒤 PR(변경 합치기 요청)을 올립니다.
4. 다른 팀원 한 명이 확인하고 합칩니다.

공통 파일인 `agents/state.py`, `project.json`, `evaluation.json`, `app.py`를 바꿀 때는 먼저 공유합니다.
처음부터 역할을 실제 이름에 강제로 배정하지 않습니다. PM·PL만 맡는 사람 없이 모두 개발에 참여합니다.

## 10분 발표

| 담당 | 시간 | 설명할 내용 |
|---|---:|---|
| A | 1분 30초 | 어떤 회사·문제를 선택했고 어떤 자료를 모았는지 |
| B | 2분 | 임베딩 선택 이유, 검색 결과와 기술 분석 |
| C | 1분 30초 | 시장·경쟁사 비교와 근거 |
| D | 1분 30초 | 평가 기준, 투자·보류 이유 |
| E | 3분 | 전체 흐름, 실행 결과, 보고서 핵심, 팀이 배운 점 |
| 여유 | 30초 | 화면 전환 |

교수님 안내대로 **README를 보면서 발표**합니다. 별도 발표자료는 만들지 않습니다.
실제 구현한 내용과 아직 못 한 내용을 구분해서 설명합니다.
